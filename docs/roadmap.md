# Morpholog: Roadmap

Status: operational. This document is what the project is *doing next*. It is forward-looking and lower-stakes than [`scope-and-ambition.md`](scope-and-ambition.md) (which fixes what Morpholog is *for*) and [`runtime-semantics.md`](runtime-semantics.md) (which fixes what the runtime *means*). When this file and design-history disagree, design-history is the historical record; this file is intent.

The "forced by a worked example" discipline binds **kernel and IR primitives**: a new `Prop` / `ValueExpr` / `Stmt` / `Value` variant earns its place only when an example needs it, never speculatively. That is where unconstrained growth is dangerous, and the bar stays high. It is *not* a brake on everything else - tooling, new worked examples, performance work, legibility surfaces, and product completeness move as soon as the direction is clear, not only when an example forces them. The bar for *adding to the language* is deliberately higher than the bar for *building around it*. This is intent, not a wish list.

## Status today

The kernel, PG adapter, CLI, polling outbox worker, and the worked examples are all in good shape. Programmes are declared-vocabulary objects. Execution is structurally inspectable through `propose_with_trace` and the CLI's `--trace` flag, including expression-internal failure-walk that identifies which sub-expression of a rejected `require` or `bind` was responsible. Predicate-scoped loading runs on both read and write paths.

The kernel's identifiers are opaque newtypes, not bare strings - subjects, the transition actor, bound variables, and predicate names - so the compiler keeps the kernel's nouns distinct and a class of runtime checks (e.g. "the actor must be a subject") becomes unrepresentable rather than enforced. Intent and declaration names are the remaining few. The migration discipline for these codebase-wide type changes lives in [`refactoring-playbook.md`](refactoring-playbook.md).

The `.morph` parser arc is closed, and the worked examples are now authored *solely* as `.morph`: each example module embeds and parses its source, with no hand-written IR to drift. A round-trip property test couples the formatter and parser. The CLI is uniformly file-path-driven - it parses whatever `.morph` you point it at and bundles no programmes: `parse`, `check`, `run`, and the read / diagnosis / operations set (`inspect`, `explain`, `verify`, `schema`, `hash`, `init`, `outbox`).

The value vocabulary now covers time and units where an example forced them: exact instants (`Timestamp`) and exact spans (`Duration`) with an explicit arithmetic rule matrix, and unit-tagged quantities (`Decimal[USD]`, `Decimal[t]` - contractual labels on exact decimals, same-unit-only algebra), all forced by the laytime example's stages. Zone-less UTC by design, and no unit registry by design: local time and unit conversions both enter as claims, never as runtime lookups.

Outbox intents are declared vocabulary too. `IntentDecl` (parallel to `PredicateDecl`) names every intent type the programme may emit; a misspelled `emit` is a validation error rather than a silent route-to-nowhere on the outbox.

Claim disciplines shipped as the language arc's second rung: `unique by`, `append only`, `current pointer by`, and `superseded via` declare the doctrine the worked examples carried as boilerplate invariants and load-bearing comments - the uniqueness rules, the append-only records, the currentness pointers and their no-fork lineages - on the predicate declarations themselves, lowered to ordinary generated invariants (visible in `guarantees` with their source clause, named in audit rows) or enforced statically (`retract` of an append-only predicate is an authoring-time error). The append-only / retractable-pointer / lineage metadata this landed is the prerequisite the gate-vs-invariant lint was waiting for.

The language's earlier second-tier rung: `define`, a named, parameterised proposition callable from gates, invariant bodies, derived domains, and other definitions (hygienic, context-free, acyclic - the contract is in [`runtime-semantics.md`](runtime-semantics.md)). The clinical-trial gate reads as five named conditions instead of one twenty-line conjunction; the AI Act example declares the statute's two-distinct-verifiers condition once and enforces it from both the gate and the permanent rule; the trade lifecycle names "the terms in force on a date". Every walker sees through calls - scoped loading, the static checks, the schema collector, the control matrix, and the explanation engine, which now reports both levels: the named business condition, then the missing claim inside it.

The compute-zone interface for non-Rust integrations is in place, and it is a pinned public contract ([`embedder-integration.md`](embedder-integration.md)): `morpholog run` closes the input boundary (named-argument codec, rejections carrying their own explanation under `--explain-on-reject`); `schema` / `schema --all` give a typed contract for every transformation, intent, and the model as a manifest; `hash` names the rules in force; `init` provisions the schema from the binary; `inspect claims --predicate` / `--named` close the read boundary; `morpholog outbox claim` / `complete` / `release` let a shell or Python deliverer participate in the lease protocol without a Rust `Deliverer` impl. A real external embedder (an open-source energy-trading system) drives a governed trade lifecycle through this contract end to end, and its integration friction is now a standing source of forcing pressure. The three-zone doctrine (compute / commit / outbox) is documented in [`scope-and-ambition.md`](scope-and-ambition.md); the round-trip compute pattern in [`outbox-sketch.md`](outbox-sketch.md).

`run --batch` ships the import shape the external embedder requested: NDJSON rows in, a receipt per row, each row its own `SERIALIZABLE` commit with its own actor, malformed rows and lawful rejections recorded as receipts rather than process failures, `--explain-on-reject` composing per row. The contract is pinned in [`embedder-integration.md`](embedder-integration.md).

The typed client travels in the binary: `morpholog generate python-client` emits a complete, deterministic, stdlib-only Python package - codecs, envelope models (derived from the `schema --result` contract the same release pinned), the subprocess adapter, and typed request / read / payload models per programme - stamped with the model hash and binary version, so an embedder speaks exactly the contract its binary speaks and drift-checks by regenerate-and-diff. Forced by two independent Python embedders hand-writing the same interface layer. One language per forcing embedder: TypeScript and friends wait for theirs.

The CLI is split by subcommand under `crates/morpholog-cli/src/commands/`. Adding a new subcommand is "add a file there, add a `Command` variant, add one dispatch arm in `main`."

## The arcs

The forward picture is a set of arcs over one IR - the language arc, the kernel arc, and the verification arc - each a different reading of the same semantic truth the kernel already evaluates and renders. None changes the constitution; each deepens what the existing thesis delivers. The forcing discipline holds throughout: kernel and surface primitives still arrive with the example that forces them; the arcs name the direction, not a backlog.

**The language arc - doctrine into declarations.** `define` (landed) named the conditions; **claim disciplines** (landed) put the append-only / retractable-pointer / lineage trichotomy and structural uniqueness on the predicate declarations, lowered to generated invariants or enforced statically. The metadata makes the gate-vs-invariant doctrine machine-checkable; the lint itself rides with the `--strict` layer. The remaining rung is **parametric patterns** (predicate-parameterised rule templates - restatement, standing, the cross-example idioms as artifacts), awaiting a worked example that genuinely reuses a pattern across domains rather than echoing its shape.

**The kernel arc - the interpreter becomes the spec.** In dependency order: invariant pruning by read/write-set intersection (the walkers exist; days of work when reached); a node-identified IR with a shared fold (ends the per-pass walker duplication; the source-location layer shipped separately - the surface-side `SourceMap` already points validation errors, lints, and runtime rejections at `.morph` declarations and statements, and the shared fold would deepen that to sub-expression granularity); a layered candidate state (base + delta overlay - the base is the pre-state, which dissolves the blocker recorded against the delta-aware rebuild); then the deep one, a **spike compiling the relational core of invariant checking to SQL** executed inside the same SERIALIZABLE transaction. That single mechanism would subsume argument-sensitive scoped loading (the compiled WHERE clause is the argument-sensitive footprint), narrow the SSI read footprint the contend bench measures, and stop commit latency scaling with in-scope state - with the sync kernel retained as the executable specification and a differential-test harness over the worked examples as the correctness argument. Spike and measure against the bench before committing to it.

**The verification arc - from explaining to proving.** `explain` answers "why not"; `inspect guarantees` and `controls` answer "what is forbidden and what must be true first". The next tier asks what the tooling cannot yet see: **vacuity and rule coverage** (statically, invariants whose antecedent cannot bind; dynamically, replaying the audit log to report which rules have ever actually constrained anything - the bitemporal-vacuity lesson made this a real wound, not a hypothetical); the **gate-protection map** (which gate protects which invariant, syntactic subsumption first - the deeper control-matrix tier already named below); and, furthest out, **bounded checking offline** (invariant mutual satisfiability, dead transformations, unreachable-without-claim questions) - an explicit revisit of the no-model-checker non-goal, never in the runtime, under the Cedar-style decidable-fragment discipline [`prior-art.md`](prior-art.md) already endorses. The same machinery is the road to bounded why-not (abduction): the repair-plan tier of the explanation engine, and the engine of the propose-refuse-repair loop the README promises for untrusted proposers.

## Imminent

With the input/output boundaries, the kind/type-compatibility layer, the intent vocabulary, and named conditions in place, `.morph` authoring is materially more trustworthy than before. Most of the enriched check has landed; one lint-grade layer remains.

The prior art and influences behind the directions below - the explanation engine, materialised claims, obligations, the substrates we reject - live in [`prior-art.md`](prior-art.md). That file is possibility pressure; this one is sequencing.



- **Enriched `morpholog check`.** The structural, kind/type, binding-flow, and actor-context passes all ship today, and the lint tier now exists: findings print as hints (stderr; stdout stays script-silent) and `--strict` promotes them to errors. Its first occupant is the **gate-vs-invariant lint** - an invariant conditioning append-only records on a retractable pointer's presence, the revocation-rewrites-history shape the discipline metadata made nameable; a hint rather than an error because the continuous-compliance reading is legitimate. What remains on the tier:
    - Unused predicate / intent declarations, `sum(x | body)` where `x` doesn't appear in `body`, unused transformation parameters, fuzzy "did you mean `MayApprove`?" suggestions on an `Undeclared` reference.

- **Source-located diagnostics (shipped).** Every finding now points at the line: the parser keeps declaration and statement spans in a `SourceMap` (`parse_program_with_sources`), validation errors and lints render as caret blocks in `check` and the shared validate gate, `check --json` emits the machine-readable diagnostics object (severity, message, byte offsets, line/column) for IDE and embedder integration, and a single-run rejection prints the violated rule's source location to stderr. Declaration + top-level-statement granularity; sub-expression spans arrive with the kernel arc's shared fold. This is the substrate the LSP work below builds on.

- **Legibility tooling - Morpholog as an explanation engine.** The runtime answers "is this admissible?"; the higher-value questions are "why not, what is still missing, and what does this model make impossible?" - the language an auditor or regulator actually needs. Almost all of it is *derivable from the IR and the existing trace*, not new kernel or surface, and all of it is **deterministic template rendering** of that trace (the `morpholog_core::format` family), **never natural-language generation**: an explanation an auditor relies on must be reproducible and faithful to the exact failing claim. No NLP or LLM in the path; the legibility comes from good predicate / transformation names plus good templates.

    **Shipped:** `morpholog explain` (a rejection rendered as a directly-missing-evidence checklist - the required claim-conjuncts the gate is missing, each paired with the candidate transformations that assert that predicate, a one-hop static lookup), `morpholog inspect guarantees` (each invariant as its rule, and for `not(...)` invariants the forbidden state named outright), and `morpholog inspect controls` (the control matrix: what must already be true before each action - every transformation's `require`/`bind` preconditions with the predicates each consults - beside what can never be true, the guarantees). All in prose or JSON. Deliberately one-hop / single-transformation in v0; present blockers, comparator failures, and bounded why-not / abduction are deferred. The carbon-credit example is the flagship for the rejection engine; the AI Act example is the flagship for the control matrix (its statute clause-to-rule mapping table is `inspect controls`, regenerated from the rules). See [`design-history.md`](design-history.md).

    **Remaining:** `inspect transformation --graph` (the body as a pre/post dependency DAG) and subject-flow profiles (clusters where the same `Subject`-kind position recurs). Both derive statically from the parsed programme; neither adds IR primitives. A deeper control matrix - pairing each gate to the invariant it protects and naming the failure mode each prevents - is a later tier on the `inspect controls` foundation. Full multi-step path-finding is bounded model checking, deferred. Predicate-kind annotations (`kind Standing` / `Evidence`) were considered and deferred - the classification is largely inferable from structure.

## Performance, when forced

The bench measures the curves that would force work here; the numbers below are the current readings (full detail in `crates/morpholog-bench/README.md`). Nothing here is forced today.

- **Single-propose scaling is linear, and the kernel is not the bottleneck.** ~1.6s per commit at 100K in-scope claims and ~1.5s for a 100K-transition replay are dominated by load + PG IO, not kernel work. Both are intrinsic to re-reading and re-indexing the full in-scope claim set each transition; the cure is materialisation, not micro-optimisation.
- **Retraction-heavy replay stays linear.** The `as-of --retract-fraction K` axis confirms it: a 50%-retract log replays in the same linear time as an asserts-only one (the `ReplaySet`'s retract is amortised `O(1)`). This was the measurement to take before sizing any snapshot/lattice work - and it says that work is **not forced**. The likely shape when it is: a checkpoint table materialising the live claim set every K transitions, plus a delta-replay path resuming from the nearest checkpoint. That is plain-PostgreSQL application logic - state-at-T is a stateful fold over assert/retract, not a time-bucket aggregate, so *not* something a TimescaleDB continuous aggregate could express.
- **Concurrent proposals on a shared predicate footprint anti-scale, and value-level partitioning does not fix it.** The `contend` scenario shows the SERIALIZABLE 40001 retry rate climbing roughly linearly with worker count while throughput falls: posts that read a predicate and write into it serialise under SSI. Crucially, the `--periods` sweep shows that sharding the writes by value (a private period per worker) leaves the retry rate flat - because `load_state` reads the whole predicate, not a value sub-range, so the read/write footprints still overlap. The `--disjoint` sweep confirms the positive half: giving each worker its own *predicate* roughly quarters the wall-clock and more than halves the retry rate. So the lever is disjoint predicate footprints (already exploited by predicate-scoped loading) or batching, not value-level sharding of one aggregate. The residual contention even when fully predicate-disjoint is consistent with PostgreSQL's predicate-lock granularity (the adjacent `Bench_*` keys likely share an index page) rather than logical overlap; confirming the mechanism would need a physical-layout control. This is also the measured 40001 rate the substrate question below requires.
- **Throughput levers, when concurrency on a hot predicate is forced.** The unit of concurrency is the read footprint the runtime loads, not the business value - so the levers, in increasing depth, are: *batch* the contending writes into one governed transition (one read-set pass for many entries, the natural shape for import / auction / settlement files); model *bounded aggregate claims* (`AccountBalance`, `EntryBalance`) so a transition reads a few aggregates instead of every base line (O(touched aggregates), not O(all lines)); and, deepest, *argument-sensitive scoped loading* - narrowing `load_state` to the predicate slice a transition needs (`JournalLine where period = p7`) rather than the whole predicate, which requires static read-set extraction with runtime parameter substitution, a real feature rather than a DB index. None is forced until a real workload needs the throughput; the bench's `contend` axis is where that pressure would first show.
- **TimescaleDB for the audit log - candidate substrate enhancement, when real scale forces it.** `morpholog.audit` is append-only and time-ordered, a natural hypertable on `committed_at`. Two wins would be real at multi-gigabyte scale: chunk exclusion for as-of window queries, and columnar compression of cold chunks (the repetitive-key JSONB payloads compress well, and compressed-chunks-are-read-only suits an immutable ledger - the strongest reason to reach for it, since the target domains produce GB-scale audit lakes). Hard constraints, because this touches the correctness substrate: single-node only (distributed hypertables drop cross-node `SERIALIZABLE`, non-negotiable, and are deprecated upstream regardless); the `transition_id` primary key must become composite with the partition column, so the as-of lookup path needs re-checking; and SSI behaviour across chunks (predicate-lock granularity, 40001 rate) must be *measured* on the partitioned shape, not assumed. It does not replace the checkpoint work above. Adopting it would be an explicit revisit of the locked PG-only substrate floor. Timescale's analytics primitives stay on the BI side, outside governed reads. Revisit only when the bench surfaces a real storage or replay problem on a real workload - not before.
- **The subprocess CLI tax is low; a long-lived run-worker is not forced.** `scripts/embedder_latency.sh` times one `morpholog run` end-to-end at single-digit milliseconds (~3ms spawn + parse + validate, plus ~6ms connect + propose + commit against a small ledger) - on the order of 100 governed transitions per second, single-threaded. That is comfortable for the lifecycle events the governed core exists for (capture, confirm, settle, approve) and for admin / audit flows. A long-lived worker (load + validate once, warm pool, HTTP or socket) earns its place only when a genuinely high-frequency path needs it - and the doctrine keeps high-frequency analytical paths out of the governed core regardless. The propose component grows with in-scope state as the `write` scenario measures; the spawn / parse / validate floor does not.

## Operational completeness

The hardening real deployment needs. Not language growth and not gated on a worked example - these move as Morpholog approaches its first production deployment. Listed, not frozen.

- **Worker supervisor.** The polling outbox worker exists and ships a `StdoutDeliverer`. Missing: a supervisor running multiple workers under restart-with-intensity, with crash isolation between deliverers.
- **Per-target circuit breakers.** A delivery target that misbehaves should be ring-fenced (back off, alert, eventually quarantine), not continue eating the worker's loop indefinitely.
- **HTTP-aware deliverer.** Once a worked example actually sends an outbox intent over the wire, an `HttpDeliverer` with the right retry/idempotency semantics.
- **Parser-side input-depth guard.** `Program::validate` already rejects expression and `for`-statement nesting past a fixed depth, so over-deep IR cannot exhaust the stack in `propose` - the teeth behind "validate untrusted IR before proposing it". The `.morph` parser has no equivalent guard: a pathologically nested source file could overflow the recursive-descent parser before it produces any IR. Deferred because in v0 you author your own `.morph` files; forced once `parse` ingests source from an untrusted origin.
- **The embedder surface, shipped and pinned.** Schema generation for transformation arguments and intent payloads, the named-argument codec in both directions (`--args-named` in, `inspect claims --named` out), the targeted predicate read, the manifest and model hash, schema provisioning from the binary, same-snapshot rejection explanations, the outcome-envelope contract (`schema --result`), and the generated Python client - each forced by the `examples/etrm_embedder/` worked embedder or its first external sibling, all pinned in [`embedder-integration.md`](embedder-integration.md). A TypeScript client and an OpenAPI surface wait for the embedder that forces them; the generated client's kind floor (no Duration / Collection models yet) moves the same way.
- **A hash-chained audit log.** `morpholog verify` already detects an edit that leaves the claims table and the audit log disagreeing; a *coordinated* edit of both is what tamper evidence addresses - each audit row carrying a hash over its predecessor, so rewriting history breaks the chain visibly. Also the substrate an exportable evidence pack (a portable, independently-checkable account of one subject's history) would build on.
- **A SQL views generator.** Analytics and BI tools want governed state in their native tongue. The answer that keeps the BI engine out of the kernel: emit plain `CREATE VIEW` statements over the claims table from the declared predicate and derived-claim vocabularies - read-only by construction, regenerated when the model changes, queryable by anything that speaks SQL. The read-side complement of `morpholog schema`.

## Language affordances awaiting a worked example

Each lands when an example actually demands the shape. None are pre-decided.

- **Higher-order authority / predicate-pattern matching.** *One* authority claim governing a *family* of transformations, instead of one per kind. The declared predicate vocabulary now provides a metadata home; the shape itself still needs a worked example.
- **Parametric patterns.** Predicate-parameterised rule templates, instantiated explicitly and expanded at load - the restatement triple, the standing pattern, the cross-example idioms shipped as artifacts instead of READMEs. The rung after claim disciplines on the language arc; it waits for the disciplines to prove the lowering-plus-metadata shape, and for a worked example that genuinely reuses a pattern across domains rather than echoing its shape.
- **Effective time as a separate axis.** As-of gives knowledge time. Effective time - the day a contract becomes binding, the period a posting reflects - is expressible as ordinary claims; combining the two gives bitemporal addressability without `valid_from`/`valid_to` schema columns.
- **Validity windows + repair transitions + exception claims.** First-class typed claims that mark an admitted assertion as in-repair, contested, or quarantined, with audit standing. No bypass flags ever.
- **Materialised derived claims.** Reports are recomputed on demand today. For long audit logs and frequent queries, materialised snapshots become forced - with invalidation modelled as ordinary claims, not as cache machinery.
- **Migrations framework.** A small one. The schema is hand-written today; with multiple deployments and an evolving claim vocabulary, a migrations story will be forced. The shape should be claim-shaped (migration as transformation, schema version as admitted claim).
- **Civil-date arithmetic.** Time arithmetic now exists where the laytime example forced it: exact instants (`Timestamp`) and exact spans (`Duration`), with instants shifting by spans, differencing into spans, and spans summing and capping. What remains deferred is arithmetic on *civil dates* - adding a span to a `Date`, the length between two dates - which is calendar arithmetic (month lengths, leap days) and awaits a worked example that needs it.
- **Port-local time as admitted claims.** The laytime example's next stage: local calendar days (the 25-hour fall-back day, "weather working days") entering as claims from an external calendar authority - `PortDay(port, local_date, starts_at, ends_at, tzdb_version)`-shaped - never as a runtime tzdb lookup. The forcing argument is replay determinism; the principle is that external interpretive facts become claims, not hidden runtime assumptions. Statement-of-Facts correction after a settled demurrage claim arrives in the same stage.
- **Unit conversions as claims.** Units themselves shipped (the laytime example's cargo tonnage and demurrage money forced `Decimal[t]` / `Decimal[USD]` - contractual labels on exact decimals, same-unit-only algebra, scaling, ratios). What remains deliberately out is everything relating one unit to another: conversion factors, FX rates, market-convention tables. Those are domain knowledge with provenance and time (whose table? as of when?), so they enter as supersedable admitted claims when an example genuinely needs one - never as kernel constants. No compound units and no unit-producing arithmetic until a worked example argues otherwise.
- **`morph fmt` (canonical formatter as a CLI).** The formatter exists in `morpholog-core::format` and is coupled to the parser by the round-trip property test. A CLI front-end (`morpholog fmt <file.morph>` or `--check` mode) lands when a project's worth of `.morph` files starts to feel like editorial drift; not before.
- **Integration / external-compute provenance.** The same primitive (claims) reaching the system's edges: external-computation results admitted as provenance claims, outbox intents acquiring delivery/acknowledgement claims, and actor authority extending to delegated and external actors. The longest-horizon direction; deliberately unspecified in detail until the embedder forces a concrete shape.

## Deliberately out of scope (revisit only with explicit reason)

The doctrinal floors - no entities/classes/services/ORM, no workflow engine, no arbitrary computation inside transformations, no BI engine, no solver runtime, no ad-hoc query DSL, no bypass flags ever - all hold here; they and their reasons live in [`scope-and-ambition.md`](scope-and-ambition.md)'s Non-goals and are not re-listed. The deferrals specific to the operational plan:

- No self-hosting. Morpholog governs business state; the compiler is Rust.
- Tree-sitter / LSP grammars: the parser is the forcing pressure. Deferred until an authoring workflow puts real demand on them.

## How to read this file

If something appears on the "awaiting a worked example" list, that's a *deliberate* hold, not a TODO. The project's central discipline is that kernel primitives arrive alongside the example that forces them; reading the list as a backlog defeats the discipline.

If a section moves from "imminent" to "landed" or from "awaiting" to "imminent", that change goes through the same review/PR loop as code changes. The roadmap moves; the doctrine in [`scope-and-ambition.md`](scope-and-ambition.md) does not.
