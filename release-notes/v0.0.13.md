12 merges since v0.0.12. The headline: one invariant outside the compiled fragment no longer costs a programme the compiled route, and every command refuses a database its binary cannot serve before the first query.

## Upgrading

- Stop every process on the database first, then run `morpholog migrate`. Two migrations are new: the coordinate the compiled checks order dates by (018), and each index requirement recording the argument position it seeks on (019). Both leave a v0.0.12 binary able to write; the last item says why it should not. `docs/install.md` now carries the whole sequence: stop, back up, `migrate --check`, `migrate`, `audit verify`, `provision indexes`, start.
- Then run `morpholog provision indexes a.morph b.morph ...` once, naming every deployed programme. It builds the statistics the planner needs to seek a large predicate (v0.0.12 walked a large predicate instead of seeking it: an ordinary posting at 100,000 entries took about 150 ms, and takes a few milliseconds again), and the indexes for the invariants that now compile. Add `--prune` to drop what no programme needs any more, statistics included.
- Regenerate the Python client. Its `open_client()` and `open_session()` now check the binary at first use, and `hash_report`, `provision_report` and `provisioned_statistics` changed shape.
- From this release, every command but `init` and `migrate` refuses a database behind or ahead of the binary, by name, before its first query. v0.0.12 and older binaries cannot be retrofitted: against a newer schema they fail one query at a time, as before, so restart every process on the new binary after migrating.
- `evaluate` reports scores as `case_bound_admission_v3`, score format version 3, since scoring follows defined calls as admission does.

## What changed in how a proposal runs

- **A mixed route, per invariant** (#407). Invariants compile one by one. The ones that compile are checked in the database over the cases the change touched, the rest by the interpreter in memory, in the programme's order, inside one transaction; the first violation or error in that order is the answer, as it always was. `check -v` says which: `compiled`, `mixed, N compiled, M interpreted`, or `interpreted`. Twelve gallery programmes that were interpreted whole now run mixed.
- **More of the language compiles** (#407, #413, #414, #424). Calls to definitions, orderings anywhere in a scope, and date comparisons through a coordinate of their own, `morpholog.date_ordinal`, are in the fragment. A rejection's witness on the compiled route now replays the kernel's own failing path, into a call's frame or a nested implication, and is held to the kernel's exactly.
- **A check bounded to a case seeks on the case's columns** (#412), and `provision indexes` analyzes the claims table on every run that applies, so a case-bound check on a large ledger no longer walks a partial index.
- **Statistics on every seek position** (#423, #426), and pruned when no programme needs their position (#425).

## For embedders

- **`provision indexes` is a pinned envelope** (#408). `--json` prints `provision_report`, in `schema --result`, the golden set and the client's `provision_indexes()`. The command takes every programme the database serves in one call: the plan is their union, a conflict in one applies nothing for any, and `--prune` acts once, after all are recorded, so there is no ordering rule to remember. Indexes kept for a programme outside the call are listed as `required_elsewhere`; a programme whose recorded requirements do not say their positions is named under `positions_unknown_for` until it is provisioned again.
- **The generated client checks the binary at first use** (#409). `open_client()` asks `hash` once before the first call and `open_session()` reads the ready line; a binary of another version, or a file whose rules are not the ones the client was generated from, is refused naming both sides. A pre-#409 binary is identified as lacking the versioned `hash` report. `Morpholog(...)` and `Session(...)` constructed directly stay unchecked, which is how a deliberately mixed pair runs. `hash_report` carries `morpholog_version`.
- **A schema behind or ahead is refused on every command** (#393). Behind names `morpholog migrate`; ahead names both versions and never advises migrating; on a proposal the refusal is the `not_committed` object. The head schema file records the migrations it embodies, so a database provisioned from the bare file is current; apply it in one transaction that stops at the first error.
- **Migration guards pin what they make.** Migration 015 no longer refuses a head-shaped `index_requirement` with the later column, so a database provisioned from `schema.sql` with no migration record replays cleanly.

## Rust API

- `plan_indexes` and `provision_indexes` take a slice of programmes and `check_named_programs` says whether a set may be named. `InvariantPlan` gained `Mixed`. `PgError` gained `SchemaAhead`, `NoProgramNamed` and `ProgramNamedTwice`. `require_current_schema` is the check every command runs. Two hidden kernel seams, `finish_staged_delta_with_effective` and `Admission::range`, serve the mixed route and say what a caller owes.

The generated Python client is regenerated and stamped v0.0.13.
