8 merges since v0.0.11. The headline: a proposal loads only the rows its body can observe, so writers on different cases stop conflicting; and the compiled checks now cover quantities and instants.

## Upgrading

- Run `morpholog migrate`. Two migrations are new: a function that orders stored instants (016), and one equality key over every stored value (017), which the compiled checks and the new keyed loads seek through.
- Then run `morpholog provision indexes <file.morph>` for every deployed programme, interpreted ones included, and add `--prune` on the last run. Every managed index is rebuilt over the new key, so the indexes from v0.0.11 are stale once the last programme is provisioned. A programme whose loads seek without their index scans the predicate computing a key per row: correct, but slower than v0.0.11 and holding the same lock.
- Regenerate the Python client. A client generated for v0.0.11 can reject the new error object as contract drift, and a v0.0.11 binary rejects a pack whose attestations carry the new role field; nothing checks versions at run time. `docs/install.md` shows one binary per project, pinned with `MORPHOLOG_BIN`.

## What changed in how a proposal runs

- **A proposal loads the rows its body can observe** (#400). Where a claim pattern fixes a position before the body runs - a literal, `actor`, or a parameter no statement rebinds - the load fetches only the rows equal there, through an index. A body that binds its key as it runs still loads the predicate whole. Under SERIALIZABLE, a whole-predicate read past thirty-two pages was one lock on the whole claims table; a keyed read leaves none. `transact` keys each act by its own arguments.
- **Compiled checks order quantities and instants** (#397). `unique by` over a unit quantity, a quantity that must be positive, and a period whose start must precede its end now compile. Where the kernel would raise while comparing, the SQL carries the error as data and reports the kernel's own error, in the kernel's order.
- **One equality key per claim position** (#399). Every join and filter compares the stored values by a key that is equal exactly when the kernel says the values are, whatever kind history stored there. The managed indexes hold the key's digest.

## Performance

- Sixteen writers, twenty proposals each, all gating on one shared predicate of five thousand rows, on the compiled route with its indexes: retries per commit fell from about 8.5 to 0.08, and commits a second rose from 60 to about 5,500 (#400). Sixteen writers on disjoint predicates: no retries at all.
- A complete-prefix evidence pack of 137,000 rows verifies in 8 MB of memory (the reported case needed about 6 GB) and exports in 16 MB where it took 1.3 GB (#395).

## For embedders

- **Evidence packs stream** (#395). `audit export` of the complete prefix writes NDJSON (pack format 4): a manifest line, the checkpoints, then every row; `audit verify-pack` and `evaluate` read it row by row, gzipped or not, and older single-document packs still verify. Breaking: `audit export` without `--from-*` or `--transition` no longer prints one JSON document; `schema --result` drops `evidence_pack` and adds `prefix_pack_manifest`; the client's `audit_export(path)` writes the pack to `path` and returns its manifest, and `EvidencePack` is gone from the client.
- **A known non-commit is something the binary says** (#383). One-shot `propose` and `transact` print an error object with a published code for every failure before or inside the proposal. The client settles a proposal only on a decided envelope or a published code; silence, a signal, garbage or a timeout is `MorphologOutcomeUnknown`, whatever the exit code. Batch receipts flush as each row finishes, and a batch that stops raises `MorphologBatchIncomplete` naming the rows in each state. Rust: `envelopes::AtomicError` is renamed `RequestError` with no alias; the Rust crates have no outside consumers yet.
- **Which incarnation of a role asserted each actor** (#391). The attestation records the role's OID beside its name, inside the Merkle leaf; older rows hash as before. `audit verify` and `verify-pack` report `role_rebindings`, a role seen under a new OID, as a finding that never changes the verdict. `verify-pack` now always prints the report, not a bare verdict.

## The instrument

- `morpholog-bench contend --prepopulate N` fills the gated predicate before timing under `--disjoint` too, the shape that shows the keyed-read change (#400).
