33 merges since v0.0.14. The headline: a refusal now names the values it was judged on, both the bindings and the two values its failing comparison compared, so an application can say why without redoing the rule's arithmetic. Admission checks only the cases a change can affect in more programmes than before, which moves the semantics version from 1 to 3.

## Upgrading

- **Start from v0.0.14.** This binary carries only the migrations after v0.0.14's schema (#516). A database that does not record v0.0.14's migration 23 is refused by name; upgrade it with a v0.0.14 binary first.
- **Stop every process on the database, back up, then run `morpholog migrate`.** `docs/install.md` ("Upgrading an existing database") has the whole sequence. Two migrations are new:
  - **024** drops the rejection log's rule that only an invariant refusal carries a witness, since a gate refusal now carries one too.
  - **025** adds `rejections.compared`.

  A v0.0.14 process started after the migration is refused before its first query, because the database is ahead of it.
- **Then run `morpholog provision indexes --check <programmes>`.** `migrate` now ends with a hint saying so (#549). Planned with the v0.0.14 binary and with this one, each on a fresh database, the gallery's index requirements are identical: 21 programmes, 319 indexes and 91 statistics objects. A programme with `or` in an invariant's consequent is different: that rule now compiles (#544) and can need more indexes. `Order(o, d) implies (Approved(o) or Waived(o))` went from one index to four.
- **Some decisions differ: the semantics version is now 3.** For the same programme, state and proposal, this release can decide differently from v0.0.14. Both changes narrow what admission checks:
  - a change that touches none of a rule's reads no longer checks that rule, and arithmetic, an extremum or a builtin over bound terms no longer widens a rule to the whole state (#529);
  - an `or` in a consequent no longer widens a rule's cases (#544).

  So a proposal v0.0.14 refused because of an old violation the proposal did not touch can now be admitted. A receipt made under v0.0.14 still verifies its evidence, and reports its evaluation as `not_re_evaluated`. Version 2 was never released.
- **Export evidence packs again.** There is one pack format now, 17, for every kind of pack (#517). A pack written by v0.0.14 is reported `unsupported_pack`, naming the format it carries; export it again from the upgraded database. A v0.0.14 verifier cannot read a pack this release writes, so upgrade verifiers with the database.
- **Python 3.12 is the floor** for the generated client (#516).
- **Regenerate the Python client.** Several envelopes gained fields: `witness` and `compared` on refusals, `asserted_in` on claims reads, `cases` in `check --json`, and `refusals` in coverage. A client generated before refuses them by design. The client is also stricter (#559). Malformed output raises `EnvelopeError` from an envelope and `CodecError` from a generated model, where it used to pass through or raise `TypeError`. A session error receipt with a code the schema does not publish now poisons the session.
- **`check` may newly fail.**
  - `check` follows the runtime into `not`, `implies`, `exists` and `forall`, and refuses a programme whose binding flow can raise an unbound variable at runtime (#547).
  - Two new hints can fail `check --strict` (#532): a rule that re-checks history when a figure changes, and a field or parameter name the Python client would refuse.
- **Gallery programmes changed.** If you copied one, compare it:
  - example 12's `from` and `to` are now `starts_at` and `ends_at` (#532);
  - example 13 records one deployment and enforces who may act (#552);
  - example 04's approval acts take only the document's id (#553);
  - two permanent events in 13 and 17 are `append only` (#532).

  Their programme hashes moved.

## What a refusal says

- **A refused gate carries its witness** (#531): the bindings at the part of the gate that failed, from the same walk that renders the trace, never the actor. It is on the rejected envelope, batch and session receipts, the rejection log and `explain`.
- **A refusal carries the two values its failing comparison compared** (#537): `compared` with the operator and both values, kept only when they fail the comparison. It is on every refusal kind, `explain` and the rejection log (migration 025).
- **`explain`'s invariant verdict carries the witness too** (#542), held to the refusal's by a test.
- **`check` names the rules a change may check whole** (#540). `check --json` gives each invariant `cases`: `bound`, or `whole` with the construct responsible. `check -v` prints them.
- **Coverage names what refused** (#546). Each transformation's coverage lists `refusals` by kind and rule, summing to `proposals_refused`. Names this programme does not declare get their own section in the prose.

## Admission

- **Arithmetic no longer widens a rule, and a change outside a rule's reads leaves it unchecked** (#529). A rule over `pre` is still checked, since it judges the change itself.
- **`or` in a consequent compiles, and bounds** (#544), as the last conjunct of the consequent or as a definition body. A conjunct after it is refused by the compiler as `disjunction_shape`, and the rule stays interpreted.

## For embedders

- **`morpholog roles move`** (#558) moves a deployment from a shared role pair to roles of its own, in one transaction. It moves only the logins you name, keeping their inherit and `SET ROLE` settings. It refuses and changes nothing when the old roles hold more than Morpholog's floor in this database, belong to another role, or when `PUBLIC` holds privileges the floor would revoke. `install.md` covers it, including how to tell whether a move committed when the reply was lost.
- **`--mentions <subject>`** (#543) on `inspect audit` and `inspect rejections`, and `mentions=` on the client, keep only the rows that name a subject: in an audit row's arguments, claims or intents, or a refusal's arguments, witness or compared values. The actor is not searched.
- **Claims reads name the transition that made each claim present** (#551): `asserted_in` on `inspect claims`, the session's `claims` and the client's reads. Read now, it is the claims table's own column, which `audit verify` does not check. Read `--as-of`, it comes from replaying the audit log.
- **The session answers `audit`, `rejections` and `ping`** (#545). The protocol is still 1.
- **The client's `init()` takes `role_prefix`** (#548).
- **The generated client is type-true** (#559). Every parsed envelope holds the types its annotations declare, and the whole package type-checks under the pinned mypy in CI. It also passes a pinned ruff with no suppressions (#543).
- **`audit verify` reports progress on stderr** (#554) every ten thousand transitions.
- **New guidance in the embedder guide:**
  - the resident session behind a web server, measured at about half the time per proposal of a one-shot `propose` (#555);
  - a deadline sealed by a witnessed checkpoint (#418);
  - why `checkpoint` reports two shapes (#556);
  - how to read names for audit rows written before parameter names were recorded (#557);
  - keeping personal data out of the record, and what that does not cover (#560).

## Evidence

- **One pack format, 17, for every kind** (#517), described under Upgrading. Each manifest names its kind and the release that wrote it.
- **Witnesses** (#515): a token whose signer's key is of another family than the signature it names is now `invalid`, where v0.0.14 said `unsupported`. An ECDSA or SHA-224 algorithm identifier carrying parameters the standard forbids is `invalid` too.

## Tested more thoroughly, unchanged in behaviour

Tests now pin the following. No behaviour changes:

- **Outbox:** a delivery lost to a worker crash is delivered again as the same intent, with the same idempotency key and payload, and the redelivery adds no audit row, claim or intent (#560). Delivery is still at least once.
- **Calendar:** property tests check the calendar laws through the evaluator (#560).
