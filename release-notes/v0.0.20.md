44 merges since v0.0.19. A deployment can now be closed, so that a login needs authority to assert any actor, and a host can enrol its own new users without reaching anyone else's identity. A refusal by a named gate names the act's parameters the gate reads, so a form can mark the field. A programme can be split into parts.

More rules run on the compiled route, a large act no longer exhausts the planner, and a read keyed inside one rule loads a dozen rows where it loaded thousands. And this release is the first to carry its own register record, signed.

Migration 031 is needed. The semantics version stays at 6: no decision changes for the same programme, state and inputs. Some duration spellings and some ill-kinded programmes that v0.0.19 accepted are now refused before anything is decided, as below.

## Upgrading

Follow the upgrade checklist in `docs/operating.md`: stop every process, back up, migrate, verify the audit, check provisioning, regenerate the clients, and start on the new binary.

- **Run `morpholog migrate`** (031). It creates `morpholog.deployment_identity`, a table holding one row that says whether the deployment is open or closed. A database without that row refuses every proposal.
- **A migrated deployment stays open**, as it was. `init`, `migrate` and `check --database-url` now print a note on stderr saying so, with the command that closes it (#826). Stdout is unchanged. Closing is opt-in: see "Closed deployments" below.
- **Run `provision indexes --check` for every programme.** Newly keyed reads (#810) and rules that moved to the compiled route (#804) can need an index a programme did not need before. On a database v0.0.19 provisioned for every gallery programme but the new example 27, this binary needed nothing new: all 426 indexes and 9 statistics objects were kept. Your programme may differ.
- **`check`, `migrate` and `provision indexes` print a coded error on stdout** when there is no report (#850). With `--json` on `check --database-url` and `provision indexes`, and always on `migrate`, a failure to connect or a schema that does not fit prints one object and exits 1: `{"status": "error", "code": "...", "error": "..."}`. The codes are `connect_failed`, `not_initialised`, `schema_behind`, `schema_ahead`, `schema_below_baseline` and `schema_record_altered`. Before, stdout was empty. The prose stays in `error` and on stderr. `migrate --check` still reports the schema states it can inspect in its own report. Pending migrations are what `migrate` applies, not a `schema_behind` error. A failure after migration work has begun gets no code.
- **A duration is ISO 8601 exact time units, or refused** (#784). The friendly form (`1h 30m`), lowercase designators (`PT6h`), fractional hours or minutes (`PT1.5H`) and a leading `+` were accepted by mistake, on the wire and in a `.morph` `duration(...)` literal. Now each is refused. A programme with such a literal no longer parses; the gallery has none.
- **`check` refuses a little more** (#815). A definition whose body is an `or` now holds its callers to a kind every branch agrees on. A caller passing a count where every branch needs a part was accepted before.
- **A closed stdout ends a command with status 141** (#811), as a shell reports for a writer SIGPIPE ended. Before, `inspect audit | head` panicked with exit 101. For `propose`, 141 means the outcome is unknown, like any other unexpected status.
- **`audit verify` counts transitions only** (#812). On a database migrated through 027, it no longer counts the baseline and activation control rows, so it agrees with `rehearse` and `evaluate`. `tree_size` still counts every row.
- **Printed output changed** in three places. Scripts that read `--json` are unaffected.
  - `provision indexes --check` and `--dry-run` list only what is outstanding, then a count of what is kept (#819).
  - `check -v` says `invariants: 18 (9 declared, 9 from declarations)` when declarations add rules (#814). Its read line is now `body read plan: all keyed`, and with `--database-url` a second line says provisioning was not checked (#851).
- **Regenerate every Python client** with the v0.0.20 binary. A client pins the binary version. What reaches existing code:
  - a `Duration` field or parameter is a `values.Duration`, not a `str`, and no longer refuses generation (#784);
  - `ClaimRead` is a `ClaimInstance` and `NamedClaimRead` a `NamedClaim`, each adding only `asserted_in` (#849);
  - `check`, `migrate` and `provision_indexes` raise `MorphologRequestError` with the code above (#850);
  - `Rejected` and `AtomicRejected` carry `related_parameters` (#833);
  - `check(with_database=True)` and the session's `ready` line carry `identity`, `open` or `closed` (#826);
  - `init()` takes `root_actor`, `root_login` and `confirm` (#843), and `audit_checkpoint()` takes `wait` (#820);
  - an explanation's `transition` carries `decided_at` (#817);
  - the view description is format 4 (#832).
- **Gallery programmes changed.** If you copied one, compare it:
  - example 03, the ledger: each journal line carries `line_no`, and `JournalEntry` declares `unique by (entry_id)` (#840, #842);
  - example 16, the release register, gains a signing key and a published record (#778);
  - example 27 is new.
- **Formats:** evidence packs stay format 19, the score report format 6, the rehearsal report format 2. The view description moves from 3 to 4.

## Closed deployments

- **`init --root-actor A --root-login L`** makes a closed deployment (#826). A login may then assert an actor only with an `ActorAssertionAuthority` grant for that actor, or a grant for its kind (below). The root actor is different: only login L may assert the root actor A, and no claim can grant it to anyone else. The login is held by OID as well as by name, so a role dropped and made again is not the root.
- **An existing deployment closes** with `init --skip-if-exists --root-actor A --root-login L`. It first lists the actors the log records that no grant names, and stops unless `--confirm` is given. Stop the writers while closing.
- **Grants to a kind of actor** (#827). `ActorKindAuthority(kind, login)` lets that login assert any actor `ActorKind` gives that kind. `ActorKindEnrolment(kind, registrar)` lets a host admit `ActorKind(x, kind)` only for an `x` the same act mints. So a host can enrol new users at sign-up, but never move an existing actor into a kind it may assert. On a closed deployment only the root otherwise writes these claims, and an actor holds at most one kind.
- A plain `init` still makes an open deployment. To require authority for every actor, initialise or close the deployment as above.

## The language

- **A programme in parts** (#793). A `.parts` manifest lists `.morph` files in order, and every command takes it in place of a `.morph`. The parts read as one text, so a programme in parts hashes as their concatenation. A part is refused where a construct could run into the next one. `check --json` places a finding in its own file.
- **A derived claim may compute nothing** (#828). With no `value` clause, its rows are its keys over the `over` condition: the claims that meet it.
- **A live derived view chooses with `if(...)`** (#829), and may hold a flag or a subject, not only a decimal.
- **A sum's body may compare, sum, and call a condition with an `or`** on the compiled route (#804). Rules of these shapes move from the interpreted to the compiled route, and `generate views --derived live` accepts them. In the gallery, `settled_within_effective_terms` in example 10 moved. Still refused: an `or` directly in a sum's body, and a sum whose body can raise inside arithmetic.
- **`generate local-days --at HH:MM`** starts each day at a local hour (#838). A GB gas day is `--zone Europe/London --at 05:00`, 23 or 25 hours long on the clock changes. `--skipped` and `--repeated` choose what a start time a clock change skips or repeats becomes. A transformation that declares `tzdb_digest` gets the sha256 of the zone file.

## For embedders

- **A refusal names the act's parameters the gate reads** (#833). A refusal by a named gate carries `related_parameters`: the act's parameters the gate's expression reads, directly or through the statements before it, in parameter order. It is a static dependency, not a verdict on which input is wrong. It is absent for an invariant and an unnamed gate.
- **Fewer rows loaded, fewer conflicts** (#810). A pattern keyed in a rule now keys the patterns around it. On the InvenTree spike at 5,000 records, `allocate` loaded 12 rows where it loaded 14,335, and 16 concurrent `complete_order` acts retried 0.6 to 0.8 times per commit, from 6.7 to 7.5.
- **A large act plans in linear memory** (#797). A check bound to hundreds of cases held each case as an `OR` arm, and planner memory grew with their square. An InvenTree `ship` of 750 allocations ran the database out of memory at 24 GB; it now takes 250 MB and 3.1 s.
- **`explain` answers for an act that reads `decided_at`** (#817). It judges the act at its read transaction's start, and names that instant.
- **`audit checkpoint --covering ID --wait 30s`** retries for up to 30 seconds while the transition is outside the stable prefix, then records the checkpoint. If the wait runs out, it gives the same coded `transition_not_covered` refusal as before (#820).
- **The view description names a key for every view** it can stand behind (#832). A predicate with no `unique by` is keyed by all its fields. A key holding a timestamp or a duration is left out, since a view column holds microseconds; the exact `_morpholog_arguments` column stands in.
- **A compiled check that added two sums**, each through a definition with a list test, failed every proposal with a SQL error (#824). Fixed.
- **A hostless database URL reaches the socket of the port it names** (#798), not the default port's.
- **The embedder guide** gains: seeding a ledger once and copying it per test with `createdb -T`, and what a copy shares (#848); keying a CI rehearsal on the binary pin as well as the programme hash (#849); what a zero `evaluate` score means (#823); the walk in a recorded order (#793); and answers from three embedder reports (#822).
- **The bind-only-to-retract hint** no longer suggests dropping a `bind` whose field an `if` branch reads (#852).

## Worked examples

- **27, the GB gas day** (#845): a nomination admitted only with the network's own receipt before the deadline, the System Average Price as a determination that names its trades, and a late trade that flags every price and statement it affects.

## Safeguards

- **Each release carries its register record** (#778). `scripts/release.sh` seals the release register with a signed checkpoint, publishes the record and its anchor with the release, and verifies them. Before it records anything, it rehearses the register's whole history. v0.0.20 is the first release with a record, so from v0.0.21 on the script also verifies the previous release's record first. The record proves what the register holds and that the designated key sealed it. It does not prove CI ran; the script checks CI before recording that step.
- **A new value kind is a worklist** (#790): the kernel matches on kinds exhaustively, so a new kind is a compile error at each place that must decide about it. A conformance harness checks every kind on the tagged wire, in the database's value key, in view columns, in the named codec and in the generated client.
- **Tests for the gaps a mutation census found** (#837).

## Rust API

Changed or removed, so code that uses them needs editing:

- `ir_builder::{transformation_typed, value_definition, defined_value}` are removed (#799).
- `with_default_user` and `with_user` are renamed `with_connection_defaults` and `with_connection_defaults_as` (#798).
- `OutboxWorker::with_compensation` is removed, and `process_available_outbox_rows` loses its compensation parameter (#818). `process_one_outbox_row` keeps its own.
- `load_scoped_state` is removed; `load_explanation_state` returns the state with its instant (#817, #852).
- `Diagnostic::render` is now `SourceText::render`, and `CheckDiagnostic::new` takes a `SourceText` (#793).
- `SessionReady::new` takes whether the deployment is closed (#826).

Added:

- Kernel: `PreparedProgram::decide`, a decision with nothing of the state copied (#792); `analysis::related_parameters` (#833); `TransitionRef::decided_at` (#817); `PredicateArgKind::{is_ordered, is_signed, sum_seed, is_declarable}` (#790); `schema::DURATION_PATTERN` and `duration_from_wire` (#784).
- Surface: `SourceText` and `Location` (#793).
- Adapter: `DeploymentIdentity`, `deployment_identity`, `close_deployment`, `initialise_closed_schema`, `actors_without_grant` (#826); `RefusedBy` and `refused_gate()` on both rejected outcomes (#833); `transition_is_covered` (#820); `PgError::{SchemaMissing, MigrationRecordAltered}` (#850) and the closed-deployment errors (#826, #827).
- CLI envelopes: `PreflightCode` and `PreflightError` (#850), `with_related_parameters` (#833), `CheckReport::identity` (#826), `CheckReport::parts` and `CheckDiagnostic::file` (#793).
