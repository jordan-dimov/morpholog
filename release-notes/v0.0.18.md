28 merges since v0.0.17. A caller that runs arbitrary code can now propose without holding the rules or the logins: `morpholog serve` keeps both behind a Unix socket, an executor role can only deliver what was admitted, and a transformation reads its decision time from the runtime, never from the caller. Rehearsal and the case-local check no longer scan what a change did not touch, so a long record re-decides in seconds. As-of reads can start from a kept snapshot instead of the first row.

Two plain migrations are needed; neither is the staged kind that pauses writers. The semantics version moves to 5: a receipt decided under 4 reads `not_re_evaluated` from this release's verifier, never a mismatch.

## Upgrading

- **Run `morpholog migrate`.** Migrations 029 and 030 are pending for a v0.0.17 database. 029 records an executor role beside the writer and reader, and narrows the writer's grant on the outbox: it keeps `INSERT` and `UPDATE` on the delivery columns, and loses table-wide `UPDATE`, so no provisioned role can change an admitted intent (#701). 030 adds the two tables `refresh snapshots` keeps (#377). Neither rewrites history. A v0.0.17 binary refuses the migrated database as ahead of it.
- **A role prefix is now at most 55 characters**, so `<prefix>executor` fits PostgreSQL's name limit. It was 57. A deployment with a longer prefix moves to a shorter one with `roles move`, which also adds the executor; `init --skip-if-exists --least-privilege` adds it to a deployment that keeps its prefix.
- **Decisions move: semantics version 5** (#673). The case-local check now seeks only the cases a change touched. Two decisions change. A rule whose antecedent errors on a case the change did not touch no longer errors the proposal; a touched erroring case still errors, and a failing case is refused rather than lost behind the error. And a rule whose `exists`, `forall`, `not`, nested rule or sum reads a case variable's name before the rule has bound it is now checked whole: version 4 bounded it to a case the scope never read, so it could admit a change that left a broken obligation unchecked. Over the shared corpus no admission or refusal moved. Refusal witnesses moved in one shape: a `unique by` rule's refusal now binds the claim being admitted to its first pattern's variables and the claim already held to the second's. `evaluate`'s scoring is `case_bound_admission_v6`.
- **`decided_at` is a reserved name** (#378). A programme that uses it as a parameter, a `let`, a `for` or quantifier binder, or in a pattern matched against stored claims is refused by `check`, by name; rename the variable. It is never silently rebound. Example 13 renamed its own.
- **Regenerate every Python client** with the v0.0.18 binary. A client pins the binary version, so a v0.0.17 client refuses this binary at its first call. What reaches existing code:
  - rehearsal rows carry `model_hash`, and an unreplayable row `because`, with `totals.unreplayable_because` (#667); the strict models refuse unknown keys by design;
  - `init`'s report carries `executor_role` (#701);
  - new: `connect_service()` and `Session.connect()` for `serve` (#700), `refresh_snapshots()` and its `RefreshSnapshotsReport` (#377).
- **Gallery programmes changed.** If you copied one, compare it:
  - example 07, chess, has one move action, `move_piece`, that works out a capture and the next turn, and two invariants keeping pieces on the board (#694, #695);
  - example 13's `verify_match` and `decide_on_identification` take no instant: both read `decided_at` (#378).
- **Evidence packs stay format 19**, the rehearsal report format 1, the score report format 6. No programme hash outside examples 07 and 13 moves.

## The language

- **`decided_at`** (#378): a timestamp a transformation body reads, given by the runtime like `actor`. It is the start of the transaction deciding the act, which the act's audit row records as `committed_at`; a replay, live or from a pack, gives each row that instant back, and a refusal's explanation replays it. It is the logical decision time, not the moment of evaluation or commit, and not the moment the SERIALIZABLE snapshot is taken: a transaction that waits after it began is decided as of its start. Only a transformation body reads it; for a rule to read a time, admit the time. A retry is a new decision at a new instant. Decision times are not in log order, and a gate on time is not a seal against a race: to order a bid against a close, admit the close as a claim and gate the bid on its absence, and even then the order is SERIALIZABLE's logical one, not the wall clock's. `explain`, which has no recorded instant, refuses a body that reads it; `--explain-on-reject` has one.
- **`check -v` names the body reads that load a predicate whole** (#396), with the statement, its rule and the definitions it went through. A read is keyed only by what the act knows before it runs. A gate summing terms in force through the selector `effective by` generates reads every key's terms; a definition keyed by a parameter does not.

## For embedders

- **`morpholog serve`** (#699): the resident runtime on a Unix socket. The programme is pinned by a required `--expect-hash`; `--presenter UID=LOGIN` maps each caller's OS user to its own database login, checked before the service listens; an unmapped caller is closed before anything is read; reads and explanations need `--grant`. The wire is the session's, unchanged. `session --expect-hash` pins the stdio session the same way (#666).
- **The executor role** (#701): `init --least-privilege` provisions `<prefix>executor`, which reads the outbox and moves a row through delivery and nothing else: it cannot change an intent, read claims or audit, or propose. Give it to the process that holds an external key.
- **Rehearsal at scale** (#673, #677, #683, #688, #689, #691, #692). A rehearsal of forty thousand register rows was stopped after more than eight minutes before this cycle's work; a hundred thousand rows now take two to five seconds on the same laptop. The case-local check seeks its cases instead of scanning, the candidate is a view over the pre-state, a replay's state is kept for the fold, and several quadratic paths in the kernel are linear. Measured figures are in the bench README. `rehearse` reports progress on stderr every ten thousand rows (#672).
- **`morpholog refresh snapshots`** (#377) keeps the admitted state after every `--every` rows of the log (default 10,000), and an as-of read replays only from the nearest one. On a 146k-row record with two thousand live claims, a read at the end fell from 4.8 seconds to at most 0.34. Run it on a schedule. The snapshots are a cache, never evidence: a read with none replays the log, and no verifier, pack, rehearsal, score or receipt reads them. A large live set gains less.
- **What `rehearse` and `evaluate` re-decide against.** Unchanged in this release, and worth restating: the prefix each row is decided against is the recorded effects applied in the one audit order, the order of effects, not the state each decision saw. A proposal that read a claim, then committed after another that removed it, sorts after the removal, so re-deciding it can find the claim gone. For a serial history the two coincide. `rehearse` reproduces effects exactly; it does not reconstruct a concurrent decision's own context (#644). `decided_at` follows the same rule: each row's recorded instant is given back, so a decision time can be earlier than a row before it in the log.
- **Operator checklists** (#665): a new page, `docs/operating.md`, lists the steps for upgrading, deploying a changed programme, closing a day, keeping as-of reads fast, serving callers you do not trust and running the executor, each linked to its explanation.
