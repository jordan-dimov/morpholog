32 merges since v0.0.13. The headline: every commit now records the hash of the programme that admitted it, the version of the semantics that decided it and the fresh subjects it drew, so a past decision can be reproduced exactly, given the programme and the semantics the record names; and each deployment's least-privilege roles are its own.

## Upgrading

- **Stop every process on the database, back up, then run `morpholog migrate`.** `docs/install.md` ("Upgrading an existing database") has the whole sequence. Four migrations are new:
  - **020** adds `audit.model_hash`: the canonical hash of the whole programme that admitted the row.
  - **021** adds `audit.semantics_version`: the version of the rules' meaning that decided it. It is only allowed on a row that has a model hash.
  - **022** adds `audit.drawn_subjects`: the subjects the act drew from `new Subject()`, in draw order, as a JSON array of strings. It is only allowed on a row that has a semantics version.
  - **023** adds `morpholog.deployment_roles`, which records this database's least-privilege roles. A database whose fixed `morpholog_writer` and `morpholog_reader` hold the floor by direct grant has them recorded. Grants through `PUBLIC` or another role do not count.

  None of the audit columns is backfilled: older rows keep their earlier Merkle leaf encodings and stay `NULL`, as they must.
- **Stop every process before migrating; the database does not do it for you.** A v0.0.13 process started after the migration is refused before its first query, because the database is ahead of it. One left running from before cannot commit a proposal: each new audit column comes with a constraint that leaves existing rows alone and refuses every new row without it. But a running outbox worker checks the schema only when it starts, and marking a delivery writes no audit row, so it can go on delivering. Migrate once, then start every process on the new binary. Rollback is restoring the backup.
- **Test suites that forge audit rows in raw SQL** must now give each new row a `model_hash`, a `semantics_version` and `drawn_subjects` (an empty array when the act drew none). A forged row without them is refused at insert.
- **Name your columns.** Column order in Morpholog's tables depends on the database's history, so a migrated database orders them differently from a fresh one. Replace any positional `INSERT` or `SELECT *` over Morpholog's tables with named columns.
- **Least-privilege deployments: migrate before `init --reset --least-privilege`.** `init --least-privilege`, with or without `--reset`, now refuses before it creates or drops anything whatever it could not provision afterwards (#503), a connecting role that may not create roles included. A reset of a database that has not reached migration 023 is refused naming `morpholog migrate`: migrating records the existing pair, and the reset then binds them again.
- **Roles shared between databases.** `migrate` now applies the privilege floor only to the roles this database records, not to whichever `morpholog_writer` the cluster holds. It warns when those roles also hold privileges in another database, as deployments provisioned before this release can. `docs/install.md` ("Moving a deployment to its own roles") gives the steps.
- **Regenerate the Python client.** The audit rows, `check_report`, `init_report` and every verification report changed shape (below). A binary the client cannot start, such as a wrong `MORPHOLOG_BIN`, now raises `MorphologError` instead of `FileNotFoundError`.
- **Upgrade every verifier with the database.** A pack that discloses a row written by this release carries a pack format version a v0.0.13 binary refuses as newer than it understands, before reading a row. Packs of older rows keep their old versions and stay readable to older verifiers.
- **`check --strict` may newly fail.** Two hints are new: a rule whose case is wider than the claim it guards, and a variable a `require` matched being named again. Eight gallery rules were respelled for the first of them, which moved five gallery programme hashes; re-pin any you pinned.
- **`generate python-client --check` now fails on stray files** in the output directory (`__pycache__` apart), so a CI step over a directory with extra files will go red.

## What a commit records

- **The programme that admitted it** (#447). `audit.model_hash` is the same hash `morpholog hash` prints: the whole programme's identity, unaffected by comments or layout. A row is now a join key back to the exact rulebook. The audit row envelopes carry it, and `AuditRow` refuses unknown fields from now on.
- **The semantics that decided it** (#458, #459). The kernel names its semantics version, and a fingerprint test holds it: a change that gives a different answer to an unchanged question must move the version. Verifying integrity does not need the named version; it reads bytes, not the evaluator they name.
- **The subjects it drew** (#448, #466). Fresh subjects are now an input to the kernel, not something it makes, and every durable commit records the ones its act drew, in order. With the programme the hash names and an implementation of the semantics version, the record holds every other input a replay needs. An explanation of a refusal replays the draws of the run that refused.
- **Each field is in the Merkle leaf**, so the leaf moved to versions 4, 5 and 6, chosen by which fields a row carries. Each pack kind gained one format version per step:

  | Pack | Before | Programme | Semantics | Draws |
  |---|---|---|---|---|
  | Complete prefix | 4 | 5 | 9 | 13 |
  | Window | 2 | 6 | 10 | 14 |
  | Selective | 3 | 7 | 11 | 15 |
  | Single document | 1 | 8 | 12 | 16 |

  A pack's version is set by the newest row it discloses, and verifiers refuse a version above or below that.
- **The programme hash's encoding is frozen** (#460). Freezing it moved no existing programme's hash (the gallery hashes above moved because their sources changed); a new construct may only add rendering for itself.

## Proofs and evidence

- **Receipts** (#462). `audit receipt <file.morph> --pack <pack> --derived <Predicate>` turns a derived read into a receipt, and `audit verify-receipt` recomputes it from a complete-prefix pack. It checks every layer: the evidence, completeness, the checkpoint, the programme, and the evaluation. It exits non-zero unless every layer holds. Window and selective packs are refused, since a derived read needs the whole prefix. The client has `audit_receipt()` and `audit_verify_receipt()`.
- **Every verification report says whether it passed** (#468). `verify_report`, `pack_verification_report` and `receipt_verification_report` lead with `passes`, and the exit code is the same answer from the same rule. It means this invocation passed every check it was asked for. Among witnesses, only an `invalid` one fails it; `untrusted`, `unverified` and `unsupported` say what could not be established.
- **FreeTSA witnesses verify** (#470). freetsa.org signs with ECDSA on P-384 over SHA-512; its witnesses were `unsupported` and are now `verified` under its root (`unverified` without anchors). Path validation now checks a certificate with its issuer's key type, and carried certificates are judged by the bytes the token holds.
- **A path this build cannot check is `unsupported`, not `untrusted`** (#498). Path search tries every issuer under a name. A path blocked only by a signature this build cannot check (a P-521 issuer, for example) makes the witness `unsupported`. It is `untrusted` only when every path was judged and none validated. The search is bounded, since a token chooses the certificates it carries.
- **Known limitation** (#499): a token whose signer's key is of another family than the signature it names (an ECDSA key and an RSA signature, say) is reported `unsupported`, not `invalid`. It never counts as verified.
- **A complete-prefix pack is NDJSON whatever its file is called**; readers go by content. Window and selective packs are single JSON documents.

## For embedders

- **Each deployment's least-privilege roles are its own** (#484). `init --least-privilege --role-prefix acme_` creates `acme_writer` and `acme_reader`, grants them this database only, and records them. The default prefix, `morpholog_`, gives the old names. `init` refuses a role name that already exists unless this database records it. `migrate` never creates a role and refuses if a recorded one is gone. `init_report`'s `writer_role` and `reader_role` are now the deployment's actual names, no longer fixed strings. The generated client's `init()` cannot pass a prefix yet (#501).
- **`check --json` reports each invariant's route** (#445): `invariants` lists every invariant as `compiled`, or `interpreted` with the reason it did not compile. The client's `CheckReport` gains the field and a `route` summary.
- **`provision indexes --check`** (#467) changes nothing and exits non-zero unless every index and statistics object the programmes need is in place: a deploy step can gate on it. The client has `provision_indexes(check=True)` and `ProvisionReport.is_current`.
- **Typed `submit_all`** (#482) on the client and the session submits several requests as one decision over `transact`. Requests satisfy an exported `Request` protocol, and CI checks the client and session with a pinned `mypy`, including that a generated request model is accepted and anything else refused.
- **The client's pins are contract** (#436): `expected_version` and `expected_model_hash` on `Morpholog` and `Session` are pinned surface, and a proposal that never started is an operational error, not an unknown outcome.
- **Diagnostics are coloured only on a terminal** (#492), and never when `NO_COLOR` is set to a non-empty value, so a pipe or a log gets plain text.
- **`docs/embedder-integration.md`** now has a table of every proposal error code, with what it means and whether to re-submit, held to the binary's list by a test.

## Writing rules

- **Two new hints** (#446, #473), described under Upgrading. `--strict` makes them errors.
- **A reserved word is named where it collides** (#472), and the refusal of a `unique by` over every field points at `require not P(...)` instead.
- **Validation measures depth before it walks anything** (#454), so a very deep definition or `xor` gets a depth refusal instead of overflowing the stack. Within the limit nothing changes.
- **Hand-built IR is held to what lowering gives** (#447, #460): generated items, sum seeds and invariant versions that the `.morph` parser would never produce are refused. Programmes written in `.morph` are unaffected.

## Documentation

- `docs/computational-model.md` states what validated Morpholog guarantees: every decision terminates and depends only on what it is given (#453).
- `docs/README.md` maps the documentation by what you want to know, with a glossary (#497). The README now says where Morpholog sits before it shows its language (#494), and the examples index offers a way in by business problem (#495).

## Rust API

- `CompiledProgram` is now `PreparedProgram`, and `PgProgram::core()` is `prepared()` (#443).
- `propose`, `propose_with_trace`, `stage_delta` and `explain` are methods on `PreparedProgram`; `eval_invariant` and `enumerate_derived` hang off `ValidatedProgram` and take a name (#455). Every kernel entry point that executes takes a `&mut dyn SubjectSource`; runtimes use `morpholog_postgres::runtime_subjects()` (#448).
- `finish_staged_delta_with_effective` and `Admission::range` moved to `morpholog_core::execution` (#444).
- `CompensationSpec::new` takes a `PreparedProgram`. `AuditRow` gains `model_hash`, `semantics_version`, `drawn_subjects` and `rung()`. `morpholog_core::SEMANTICS_VERSION` is new.
- `passes()` on the three verification reports; `WitnessesReport::any_invalid` is replaced by `passes` (#468).
- `morpholog_surface::Diagnostic::render` takes the colour choice (#492).
- `DeploymentRoles` and its helpers in `morpholog-postgres`; `LeastPrivilegeReport`'s role fields are strings (#484). The receipt API is `parse_receipt`, `ParsedReceipt` and `reproduce` (#462).

The generated Python client is regenerated and stamped v0.0.14.
