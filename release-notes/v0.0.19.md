32 merges since v0.0.18. A host has less to write. More of what it used to restate now lives in the programme: a branch, a pass over every matching claim, a figure named once, a typed parameter, and a gate that follows a tree up through a condition that calls itself. A rule can range over a grid built from a claim's bounds, and a commitment can be held to its reveal. Writers conflict less: more reads load only the rows a decision names, not a whole predicate. And generated views do more of the reading: they describe themselves, compute derived claims live, and show each predicate's history.

No migration is needed. The semantics version moves to 6: a receipt decided under 5 reads `not_re_evaluated` from this release's verifier, never a mismatch.

## Upgrading

- **No migration.** The schema head is still 030, so this binary runs on a v0.0.18 database as it is.
- **Run `provision indexes` again for every programme.** The new keyed reads (#732, #738, #769) and live derived views (#741) seek on positions that v0.0.18 did not index. Without the indexes the reads stay correct but scan, and concurrent proposals conflict as before. `provision indexes --check` says what is missing.
- **Decisions move: semantics version 6** (#718). A value admitted into a claim, or emitted into an intent, must be of the kind its field declares. Before, a subject could land in a `Date` field, a bare decimal in a `Decimal[USD]` one, or a quantity in another unit, and the claim contradicted its own programme. Now each is a kernel error naming the field (`claim_kind_mismatch`, `intent_kind_mismatch`), and nothing is written. Claims already stored that way are untouched.
- **A decimal is admitted as written, or refused** (#761):
  - a tagged decimal written `1e10`, `+1`, `01` or `1.` is refused, as the named codec already did;
  - a decimal with more than 28 fractional digits, or a coefficient past 96 bits, is refused, where before it was rounded.
- **`check` refuses more.**
  - A definition named like a bare-word builtin (`if`, `periods`, `period_index`, `period_start_of`, `digest`) is refused by name (#755).
  - Under `--strict`, two new hints fail a programme that passed before: a sum calling a definition with a wildcard argument (#748), and a sum holding an `or` whose branches can hold together (#751).
- **Regenerate every Python client** with the v0.0.19 binary. A client pins the binary version. What reaches existing code:
  - a commit's receipt carries `drawn_subjects`, required (#765);
  - every `kernel_error` carries `kind`, and the client refuses one without it (#718);
  - `invalid_arguments` carries `parameter` when one argument is at fault (#766);
  - the rehearsal report is format 2: `would_error` rows carry `kind` (#718);
  - the client's decimal reader and writer refuse what the binary refuses (#761).
- **Session and `serve` errors are shorter** (#766). They no longer suggest running `morpholog schema`, and no longer name the server's file. One-shot commands keep the hint.
- **A large record may need a PostgreSQL setting** (#769). Under SERIALIZABLE, every read leaves predicate locks. They block nothing. But once one transaction holds more than 32 of them under the claims table, PostgreSQL replaces them with one lock on the whole table, and conflicts between unrelated proposals become more likely. With sixteen allocators on a 50,435-part tree, 7 of 8 runs at the defaults retried 0.45 to 0.51 times per commit; with `max_pred_locks_per_transaction = 256` they were about 0.2. On that machine, at 100 connections, the setting took 6.7 MiB more shared memory. It needs a restart. The embedder guide says how to tell whether a deployment needs it. #772 tracks the wider question.
- **Building from source needs Rust 1.100** (#770). Release binaries are built by 1.100.0, and now check integer overflow instead of wrapping silently (#775). A reachable overflow would panic, and would be a kernel defect. None is known.
- **Gallery programmes changed.** If you copied one, compare it:
  - examples 18 and 21 use `x in (a, b)` (#730);
  - example 23 gains hourly prices (#757);
  - examples 25 and 26 are new.
- **Formats:** evidence packs stay format 19, the score report format 6. The rehearsal report is format 2. The description `generate views --describe` writes is new, at format 3.

## The language

- **`if` / `else`** in a transformation (#753). Only the branch taken runs. `if` and `else` are not reserved words.
- **`for Pattern(...)`** (#754): one pass per claim the pattern matches, in the canonical order of the claims' arguments, so every platform runs them alike. Its read is keyed.
- **A definition that names a figure** (#755): `define allocated(item) = (sum(...))`, read wherever a value stands.
- **A parameter's declared kind** (#756): `transformation cancel_order(order, force: Bool)`. The schema and the client type it. A wrong-kind argument is the kernel error `argument_kind_mismatch`.
- **A condition that calls itself** (#768, #769). A `define` may call itself, directly, in shapes `check` can bound. That lets a gate follow a tree where the record holds only each node's parent. Loops in the data end. Mutual recursion is still refused. A rule that reads one is checked whole on every change to what it reads. Only a gate that walks one link up from a known node loads just the chain above it.
- **A rule ranges over a grid** (#757): `forall h in periods(start, end, duration("PT1H"))`, on the interpreted route.
- **`digest(...)`** (#758): a `sha256:` subject over values, so a sealed bid can be held to its reveal. The Python client computes the same digest.
- **Smaller things:**
  - `true` and `false` literals (#730);
  - `x in (a, b)` (#730);
  - `new Subject()` written inline in `admit` or `emit` (#752);
  - a misfit argument error prints its operators as written (#718).

## For embedders

- **Fewer conflicts between writers that touch different rows.** A read is now keyed:
  - by a value an earlier `bind` found (#732). On the InvenTree spike, retries fell from about 5.5 to 0.31 per commit;
  - by the elements of a list argument (#738);
  - up a tree from a known node (#769).

  `check -v` marks a whole read of a predicate the same act writes (#730).
- **Generated views:**
  - `--describe PATH` writes a description of the views, pinned in `schema --result`, with `read_view_surface()` in the client (#740);
  - `--derived live` computes derived claims in the view itself (#741);
  - `--history` adds a view of each predicate's history from the audit log (#750).
- **Receipts:** `drawn_subjects` lists every subject an act drew, in order, including any that reached no admitted claim (#765). `parameter` names a malformed argument (#766). `kind` classifies a kernel error (#718).
- **One view for every write** (#728): the embedder guide shows a single host view that serves every write a family exposes. It uses an allow-list of names, passes the body through, takes the actor from the login, and gives each outcome its own HTTP status. The InvenTree spike measured it.
- **The compiled route** hands an invariant to the kernel when a stored value drifted from its declared kind. It used to give a kernel error (#719).
- **A load past PostgreSQL's parameter limit** widens its keys, and is refused before it is sent if it still cannot fit (#740).

## Worked examples

- **25, stock allocation** (#753 to #756, #768): shipping visits every allocation, splitting or whole. A line takes stock of any variant below its part, and the gate follows the variant tree.
- **26, sealed bids** (#758): a bid is a digest, and the reveal is held to it.
- **23, delivery hour limits**: hourly prices on a grid (#757).

## Safeguards

- The kernel's purity check now reads resolved paths, so a renamed import of the clock, the environment, the file system or the time-zone database is caught (#774). It is a tripwire, not a proof.
- A match in the kernel names every variant it handles, so a new construct is a warning at every place in the kernel that must decide about it (#771).
- A dependency update in this repository takes only releases at least a week old (#770).

## Rust API

Changed, so code that uses them needs editing:

- `Definition::body` is a `DefinitionBody`, not a `Prop` (#755).
- `Prop::In` takes a `ValueExpr` source, not a `Term`, and `Lint::LargeGrid` names its `owner`, not its `transformation` (#757).
- `Builtin::arity()` and `ValidationError::BuiltinArity::expected` are an `Arity`, not a `usize` (#758).
- `ReadFilter::resolve` pairs each position with a `Key`, not a value (#732, #738, #769).
- `render_views` takes a `DerivedSource` and a history flag (#741, #750).
- In the CLI's envelopes, `ErrorReceipt::new` and `RequestError::new` take the error's kind, and `TracedError::new` takes the `EvalError` (#718).
- The lexer's `Token::ReservedBoolLit` is `Token::BoolLit` (#730).
