23 merges since v0.0.15. Rules can now range over the hours, or any fixed periods, of an interval: `periods(from, until, step)` builds the grid inside the rule, and a rule says how long a window may be before the grid is built. Unary minus arrives as plain sugar, a definition can be called by the names of its parameters, and a literal in a programme is a parsed value rather than text, so two spellings of one value are one programme. That last change moves the programme hash of any programme whose literals were not already in their canonical spelling. A moved hash touches the generated client's startup check and the derived SQL views, so read Upgrading before you deploy.

No decision changed: the semantics version stays 3. No migration is needed: a v0.0.15 database is current. The generated client gains typed methods for scoring, guarantees, a covering checkpoint and session-side explain, and it decodes quantities with their unit, which is a change to what your code receives.

## Upgrading

- **No migration.** The schema is unchanged since v0.0.15; `morpholog migrate --check` reports the database current. A v0.0.15 database serves this binary as it is.
- **Some programme hashes move.** A literal is now a value, and the canonical encoding is 2 (#600). A programme whose literals were already in their one spelling keeps its hash; one that wrote `span(P1Y)`, `duration(PT90M)` or a timestamp with an offset gets a new hash, because those are now the same programme as `span(P12M)`, `duration(PT1H30M)` and the instant in `Z`. `1.50` and `1.5` stay two literals, since a figure computed from one keeps its scale. In the gallery only the charging-years example moved. What to do:
  - run `morpholog hash` on each programme you serve with the new binary and compare it with the hash you pinned; update any deployment metadata or external reference that names the current programme by hash;
  - regenerate every generated Python client with the v0.0.16 binary whether or not the hash moved (below); where it moved, a client generated under v0.0.15 refuses the programme at its first call, and a resident session refuses to open, so start new sessions and drain the old ones;
  - **derived SQL views.** A generated view reads only the derived cache rows written under its programme hash. Where the hash moved, run `morpholog generate views`, apply the new views, then `morpholog refresh derived` for that programme; until the refresh, the regenerated views return no rows. This touches read projections only, never admitted claims or audit history. The embedder guide has the sequence;
  - keep the old hash and the programme as released under it wherever it admitted transitions. Audit rows keep the hash of the programme that admitted them, `audit verify` is unchanged, and the new hash is a new identity under the new encoding, not a sign that any decision changed. Do not rewrite historical hashes to the new value.
- **The formatter rewrites spellings.** `P1Y` prints as `P12M`, `PT90M` as `PT1H30M`, an offset timestamp as its `Z` instant, and `0 - x` as `-x` (#600, #601). A programme committed byte-exact from the formatter's output can change with this binary while its meaning does not.
- **`check` may newly fail.**
  - A decimal the exact type cannot hold, a date that does not exist or a malformed instant is a parse error at its span (#600). Before, such a literal was accepted and silently matched nothing, or failed later.
  - `check --database-url <url>` and `check --against <file>` (#575) are new and refuse a programme that no longer fits the stored claims or a sibling programme's declarations; they run only when asked.
  - A `periods` grid without its window gate or with a computed step is refused by name (#603); a grid whose gate still allows more than ten thousand periods is a hint, which fails `check --strict`.
  - `check` no longer reports `EmptySumUntyped` (#597): the checker types every empty sum, and a hand-built seed it disagrees with is `SumSeedNotFaithful`, naming both.
- **Validation widens on two shapes, and some input contracts change** (#595, #597). An empty sum whose target the old pass could not type, an outer-bound quantity or a builtin over a duration, was refused and now validates, with the typed zero (`0 t`, `PT0S`). A parameter used in `p + sum(...) <= 10` is now typed Decimal, and one used in `p <= cap * 2` with a `Decimal[t]` cap is typed `Decimal[t]`; if your programme has either shape, `morpholog schema` and the generated client's models change accordingly.
- **Regenerate every Python client**, with the v0.0.16 binary, whether or not the programme hash moved: a generated client pins the binary version as well as the programme hash, so a v0.0.15 client refuses this binary at its first call. Several envelopes also gained fields, and the strict models refuse an unknown key by design: `needed_by` on each index of the provision report (#578), `row` on the session's explanation (#591), `below_baseline` on `migrate --check` (#574), the new `guarantee` envelope (#579), the `checkpoint_refusal` envelope (#589). Two behaviours change for existing code:
  - a tagged quantity decodes to `values.Quantity(amount, unit)` on claim instances, audit rows, witness and compared values, where v0.0.15 gave a bare `Decimal` and dropped the unit (#564). Generated intent payloads still give the amount as `Decimal`, after checking the unit. Where code read a quantity field:

    ```python
    # v0.0.15
    amount = claim.args[2]            # Decimal("100"), the unit lost

    # v0.0.16
    quantity = claim.args[2]          # Quantity(Decimal("100"), "MWh")
    amount, unit = quantity.amount, quantity.unit
    ```

    The field index is illustrative. Check the unit rather than discard it;
  - `audit_witness(...)` and `audit_checkpoint(witnesses=[...])` raise `MorphologWitnessFailed` when a timestamp authority fails after the checkpoint was stored (#592). Before, the client returned the checkpoint as a success and the witness was silently missing. The checkpoint is recorded, not rolled back: `exc.checkpoint` is the head as stored, with every witness that did arrive, and `exc.retriable` is true. Retry with `audit_witness(tree_size, witnesses)` against the same tree size; a proof already stored is not stored twice, and nothing records a second checkpoint.
- **Index plans.** Planned with the v0.0.15 binary and with this one, each on a fresh database, the index requirements of the twenty gallery programmes both can parse are identical: 286 indexes and the same statistics objects. The three programmes v0.0.15 cannot parse (10, 15 and 23, for the named definition call, the unary minus and the grid) bring the whole gallery to 23 programmes and 339 indexes. The report's new `needed_by` names the rule behind each index, so a new line after an upgrade explains itself (#578). Run `morpholog provision indexes --check <programmes>` before writes resume, as the install guide's upgrade sequence says.
- **Gallery programmes changed.** If you copied one, compare it:
  - example 15 gains a credit note, reversing a billed line with its figures negated (#601);
  - example 19's hash moved with the encoding (#600);
  - every pattern with three or more wildcards is spelled by the fields it reads, across twelve examples (#601), with no hash change;
  - example 10's selector call is spelled by its parameter names (#594), with no hash change.

## The language

- **A grid over instants** (#603). `periods(from, until, step)` is the start of every `step`-wide period that meets the half-open window `[from, until)`, as a collection of timestamps, anchored at the Unix epoch in exact nanosecond arithmetic. A rule that must hold in every hour of a trade writes `let hours = periods(starts_at, ends_at, duration(PT1H))` and ranges over `hours` with `forall` or `sum`, or directly with `for`. A window off the grid meets one period more than its length holds, so alignment is one identity: `(until - from) / step = sum(1 | h in hours)`. The grid's size is the rule's own: the step is a literal, and the call must follow `require until - from no_longer_than duration(...)` with a literal bound, earlier in the same transformation. Validation refuses it otherwise, and no kernel constant caps the count. A loop binder over a grid is a timestamp before its first use. No zone and no calendar: a local day's bounds enter as a claim, and a 23-hour day gives 92 quarter-hours with no special case. Grids live in transformation bodies; an invariant over a generated grid waits for the rule that forces it.
- **Unary minus** (#601). `-x` is `0 - x`, nothing more: no new node, decimals only, and `-100` is a subtraction over the literal, never a signed literal, so a claim argument still takes no sign. The formatter prints `0 - x` back as `-x`; the hash is unchanged.
- **A definition is called by the names of its parameters** (#594), `trade_terms_in_force_on(trade: trade, as_of: d, ..)`, a generated `effective by` selector's included. The IR stays positional, so no hash moves.
- **A literal is a value** (#600). The IR holds parsed decimals, dates, instants, durations, spans and quantities, read once at the source. A text the type cannot hold is a diagnostic at its span, never rounded in.
- **One kind inference** (#595, #597, #598, #599). The static checker is the one place kinds are inferred: it owns the parameter contract that `schema`, `generate python-client` and `--args-named` read, types every empty sum, and validation keeps the contracts it observed so reading one is a lookup. Decisions did not move.

## For embedders

- **`check --database-url <url>`** (#575) compares the programme with the claims the database holds: a stored claim with another arity, kind or unit is an error on the declaration, and a stored predicate nothing declares is a hint. **`check --against <file>`** refuses a predicate two programmes declare differently, with no database. Python `check(with_database=True)`. The guide's deploy sequence runs both.
- **`migrate --check` reports a database below the baseline** (#574): `below_baseline` names the release to upgrade with, still exiting non-zero.
- **`provision indexes` names what needs each index** (#578): `needed_by` lists the invariants and transformations behind it, for the programmes named in the call, and the printed plan ends each line with them.
- **`inspect guarantees --json` is a pinned envelope** (#579), shape unchanged, and the client's `guarantees()` returns typed models (`from` becomes `from_clause`). A rule generated by `effective by` names its clause (#588).
- **The client scores its programme against history** (#577): `evaluate(pack=None, *, train_until=None)` returns a typed `ScoreReport`, offline from a pack or from the client's database. A programme the binary cannot score raises `MorphologError`: not evaluated, which is not refused.
- **`audit checkpoint --covering <transition_id>`** (#589) succeeds only with a head that contains the transition. A committed transition still outside the stable prefix is a coded refusal on stdout, `transition_not_covered`, with nothing recorded; the client raises `MorphologNotCovered`, retriable. The witnessed-close pattern is checkpoint covering the close, then `audit witness --tree-size`.
- **The session answers `explain`** (#591), the same explanation as the one-shot command plus the request row, recording nothing; the client's `Session.explain()` is non-commitful. Measured at 5 to 6 ms per call against about 15 ms one-shot.
- **Client fixes from the v0.0.15 upgrade reports** (#564): `envelopes.to_json()` prints a decoded envelope for reading, and `hash()` no longer returns a stale startup report.
- **New guidance:** what holds when a ledger outlives its programme, and what a reshaped predicate does to stored claims (#572); `exists` binds every free variable in its body, `sum(1 | body)` counts, `inspect outbox`, one client per process, checkpoint before an export a read depends on, and what a decimal's stored text is (#593); where a transformation's contract comes from (#599); the audit tail and extension workers (#572).

## Worked examples

- **23, delivery-hour limits** (#603). A power book's cap that holds in every hour a trade touches, the hours computed from the trade; a day product takes its window from a published calendar day of 23, 24 or 25 hours.
- **22, residue classes** (#590). Two textbook theorems made finite by a change of representation: the record verifies the finite part, keeps a proof assistant's report apart as testimony, and lets a conclusion stand only on both.
- **15** gains the credit note it had listed as not covered (#601): the committed line's figures negated, computed by the act, never re-rounded.

## Rust API

- `Value` holds typed payloads: `Decimal(LiteralDecimal)`, `Date`, `Timestamp`, `Duration`, `CalendarSpan`, `Quantity { amount: LiteralDecimal, unit }`; `Value::decimal`, `date`, `timestamp`, `duration`, `span` and `quantity` parse text; `literal_value` is gone and `From<&Value> for EvalValue` is total; `CANONICAL_ENCODING` is 2 (#600).
- `ValidatedProgram` is no longer `Copy` and carries the contracts; functions that took it by value borrow it, and `eval_invariant` and `enumerate_derived` take `&self` (#598). `ValidationError::EmptySumUntyped` is gone; `SumSeedNotFaithful` gains `found` and `expected`; `SumSeed` has a `Display` (#597).
- `Builtin::Periods`, `ir_builder::periods`, `ValidationError::PeriodsUnbounded`, `Lint::LargeGrid` and `LARGE_GRID_PERIODS` (#603). `PeriodSpanNotPositive` now also names `periods`.
- `in_force_signature` and `InForceSignature` (#594).
- `create_checkpoint` takes `covering: Option<Uuid>` (#589).
- Dependencies: `rustls-webpki` 0.103.16 and `webpki-roots` 1.0.10, for RUSTSEC-2026-0382 and RUSTSEC-2026-0381, published after the bump merged.

The generated Python client is regenerated and stamped v0.0.16.
